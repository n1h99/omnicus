# Лид-формы Facebook / Instagram → Omnicus → CRM

Пошаговая инструкция для подключения нового проекта и дальнейшей работы.
Основана на интерфейсе и настройке, проверенных с пользователем 1 октября 2026 года,
Graph API `v26.0`. Названия пунктов Meta могут отличаться в зависимости от языка и типа приложения.

## 1. Что получится

Клиент заполняет встроенную рекламную форму Facebook или Instagram. Заявка появляется
в Omnicus, затем — в подключённой CRM. Если человек уже есть в CRM, система проверяет
совпадение, чтобы не создавать лишнюю карточку. Для действительно нового лида
в рабочем режиме может отправляться уведомление в настроенную Telegram-группу.

Это подключение именно **встроенных лид-форм**. Формы на сайте и реклама, которая
открывает переписку в WhatsApp, подключаются иначе. У формы Instagram также нужно
определить связанную Facebook-страницу.

Сначала включается безопасный предпросмотр без создания карточек. Рабочую доставку
пользователь включает отдельно, когда убедится, что подключён нужный проект.

## 2. Что подготовить до начала

Попросите владельца рекламы подтвердить, что используются лид-формы, и предоставить:

- Ссылку на Facebook-страницу и название нужной формы.
- Доступ вашему Facebook-профилю к странице и её лидам; при необходимости — к связанному рекламному аккаунту.
- Доступ к Meta-приложению, через которое будет работать интеграция.

Доступ к рекламному кабинету сам по себе не подтверждает доступ к лидам страницы.
Если в Meta настроены отдельные права на лиды, владелец должен проверить там доступ
пользователя и приложения/CRM. Пароли от чужого Facebook-профиля не нужны.

В Omnicus администратор заранее должен подготовить:

- Нужный проект и активное соединение с нужным проектом CRM.
- Ваше право управлять интеграциями.
- Поддержку Meta lead forms на стороне CRM. Для новой установки это разовая задача администратора, не пользователя.
- Адрес **API Omnicus** для webhook. Он может отличаться от адреса сайта.
- Уведомления CRM в нужную Telegram-группу, если они требуются.

Токены этой интеграции сохраняются в Omnicus. Пользователю не нужно заменять
Railway-переменные WhatsApp, CRM или других каналов.

### Важно для нескольких проектов

В текущей версии одна настройка Omnicus связывает один проект с одной Facebook-страницей;
у этой страницы можно указать несколько форм. Page ID после сохранения не меняется.

Webhook содержит ID проекта. **Не заменяйте уже работающий Page callback другого
проекта в том же Meta-приложении.** Если он занят, администратор должен согласовать
отдельное Meta-приложение либо доработку общей маршрутизации. Простое повторение
настройки с новым адресом может отключить получение заявок старым проектом.

Созданное Meta-приложение и успешная проверка администратором ещё не означают,
что оно допущено к работе со всеми клиентскими страницами. Для внешних пользователей
могут потребоваться App Review, соответствующий уровень доступа к разрешениям
и проверки бизнеса. Эти ограничения решает владелец приложения.

## 3. Получить Page ID, Form ID и токен страницы

Все значения в фигурных скобках ниже — placeholders: заменяйте их своими ID,
не оставляйте фигурные скобки. ID приложения, страницы, формы и проекта Omnicus —
разные значения.

### 3.1. Создать пользовательский токен

1. Откройте [Graph API Explorer](https://developers.facebook.com/tools/explorer/).
2. Справа выберите **своё Meta-приложение**, версию `v26.0` и пользовательский токен — **User Token**.
3. В проверенном подключении использовались разрешения:
   `pages_show_list`, `business_management`, `leads_retrieval`,
   `pages_read_engagement`, `pages_manage_metadata`, `pages_manage_ads`.
4. Нажмите **Generate Access Token / Создать маркер доступа**. В окне Facebook
   подтвердите доступ к нужной странице. Если разрешения недоступны, вернитесь
   к владельцу приложения: случайный другой токен эту проблему не решит.
5. Выберите метод **GET**, в строке запроса введите следующее и нажмите **Submit / Отправить**:

```text
me/accounts?fields=id,name&limit=100
```

Найдите страницу по названию. Её `id` — ваш `{PAGE_ID}`. Если страницы нет,
проверьте выданный доступ и выбор страницы при авторизации; при большом числе
страниц список может быть разбит на несколько страниц выдачи.

### 3.2. Продлить пользовательский токен и получить Page Token

1. Откройте [Access Token Debugger](https://developers.facebook.com/tools/debug/accesstoken/).
2. Вставьте полученный **User Token**, нажмите **Debug / Отладка**.
3. Проверьте приложение и тип **User**, затем нажмите **Extend Access Token / Продлить маркер доступа**, если кнопка доступна.
4. Скопируйте **новый токен из результата продления**, а не старый из верхнего поля.
5. Вернитесь в Explorer и вставьте его в поле **Маркер доступа**. Повторно
   нажимать Generate Access Token не нужно: это может снова выдать краткосрочный токен.
6. Выполните **GET**:

```text
{PAGE_ID}?fields=id,name,access_token
```

Поле `access_token` в ответе — **токен страницы**, который нужен Omnicus.
Сохраните его в защищённом хранилище и вставьте в поле токена Explorer
для следующих запросов. Сам User Token в настройки Omnicus не вставляйте.

Один раз проверьте полученный Page Token в Debugger: правильные приложение и
страница, тип **Page**, токен действителен. Запишите даты **Expires** и
**Data Access Expires**, если они указаны. `Never` в одном из полей не означает,
что доступ невозможно отозвать или что остальные сроки не нужно контролировать.
Если продление недоступно или получился неверный тип токена, не продолжайте
с заведомо истёкшим токеном — нужна проверка владельцем приложения.

### 3.3. Найти форму

С Page Token в Explorer выполните **GET**:

```text
{PAGE_ID}/leadgen_forms?fields=id,name,status&limit=100
```

Найдите нужную действующую форму по названию и сохраните её `id` как `{FORM_ID}`.
Если форм много, учтите пагинацию. Для нескольких форм одной страницы запишите
все нужные ID. Не подключайте посторонние формы «на всякий случай».

Для проверки вопросов выбранной формы выполните **GET**:

```text
{FORM_ID}?fields=id,name,questions
```

В текущей версии Omnicus распознаёт `full_name`, `email`, `phone_number` и
`country_of_residence:` — у последнего ключа есть двоеточие. Другой пользовательский
вопрос о стране не обязательно попадёт в поле страны CRM. Если ключи отличаются,
передайте администратору список вопросов **без реальных ответов клиентов**:
настройка произвольного сопоставления этих полей в панели пока не предусмотрена.

Не пересылайте целиком ответы Explorer с токенами: секрет может оказаться не только
в `access_token`, но и внутри ссылки `paging.next`.

## 4. Сохранить подключение в Omnicus

Откройте нужный проект → **Connections → CRM integration → Meta lead forms → Connection settings**.
Если блока нет, проверьте активное соединение проекта с CRM и права на интеграции.

| Поле                       | Что указать                                                             |
| -------------------------- | ----------------------------------------------------------------------- |
| Facebook Page ID           | ID нужной Facebook-страницы                                             |
| Form IDs (comma-separated) | ID нужных форм этой страницы через запятую                              |
| Graph API version          | `v26.0` для описанного подключения                                      |
| Page access token          | Page Token из шага 3.2                                                  |
| Meta App Secret            | Секрет именно выбранного Meta-приложения, **не его числовой App ID**    |
| Webhook verify token       | Новый случайный секрет длиной от 32 символов; тот же понадобится в Meta |

App Secret находится в настройках соответствующего Meta-приложения
**Settings / Настройки → Basic / Основное**. Копируйте существующий секрет:
сбрасывать его, особенно у приложения с работающим WhatsApp, не нужно.

Webhook verify token можно сгенерировать менеджером паролей. В Windows также
можно выполнить в PowerShell эту команду: результат попадёт в буфер обмена.

```powershell
([guid]::NewGuid().ToString('N') + [guid]::NewGuid().ToString('N')) | Set-Clipboard
```

Сохраните verify token безопасно: после сохранения Omnicus не показывает секреты повторно.

1. Нажмите **Save disabled configuration**.
2. Нажмите **Test access**. Сообщение `Request completed. Check the status below.`
   означает завершение запроса; после успешной проверки становится доступен **Start preview**.
3. Нажмите **Start preview**, прочитайте подтверждение и нажмите **OK**.
4. Убедитесь, что статус — **PREVIEW ONLY**.

Предпросмотр позволяет получать заявки и сверять их с CRM, но не создаёт карточки
и не отправляет уведомления. **Test access** проверяет доступ к странице, формам
и CRM; он не заменяет настройку webhook и проверку реальной заявки.

## 5. Подключить webhook в Meta

В блоке **Webhook path** Omnicus нажмите **Copy path**. Копируется только путь,
например `/webhooks/meta-leads/{PROJECT_ID}`. Добавьте перед ним адрес API,
который дал администратор, без повторного слеша:

```text
https://{API_DOMAIN}/webhooks/meta-leads/{PROJECT_ID}
```

В текущей установке API находится на `https://api.omnicus.app`, а сайт —
на `https://omnicus.app`. Для другой установки адрес уточняется отдельно.
Адрес страницы настроек `/api/v1/projects/.../meta-leads` не является webhook.

1. Откройте [Meta Apps](https://developers.facebook.com/apps/) и выберите то же приложение.
2. В использованном интерфейсе путь такой: **Сценарии использования → Получение
   рекламных лидов и управление ими с помощью Marketing API → Настроить → Webhooks**.
   В другой версии кабинета Webhooks может быть отдельным пунктом.
3. В выборе объекта/продукта укажите **Page**, не User и не WhatsApp Business Account.
4. Если уже указан другой рабочий callback, **не заменяйте его** — см. ограничение из раздела 2.
5. В **Callback URL / URL обратного вызова** вставьте полный адрес из примера выше.
6. В **Verify token / Подтверждение маркера** вставьте тот же секрет, который
   сохранили в поле Webhook verify token в Omnicus. Это не Page Token и не App Secret.
7. Проверку клиентского сертификата для этого подключения не включайте.
8. Нажмите **Verify and save / Подтвердить и сохранить**.
9. В списке полей Page найдите **leadgen** и включите **Subscribe / Подписаться**.

Остаётся подписать на приложение саму страницу. В Explorer выберите то же
приложение, Page Token и выполните **GET**:

```text
{PAGE_ID}/subscribed_apps?fields=id,name,subscribed_fields
```

Если у этого приложения уже есть другие `subscribed_fields`, сохраните их:
новый список должен содержать прежние поля **и** `leadgen`. Не удаляйте подписки
других интеграций. Для нового подключения без других полей выберите **POST**:

```text
{PAGE_ID}/subscribed_apps?subscribed_fields=leadgen
```

Ожидаемый ответ — `{"success":true}`. Это нормальная отдельная операция:
подписка на поле в настройках приложения и подписка самой страницы нужны обе.
Два уровня подписки показаны и в [официальном примере Meta](https://github.com/fbsamples/lead-ads-webhook-sample/tree/main/postman)
(пример архивный; его старую версию API копировать не нужно).

## 6. Проверить одну тестовую заявку

1. Откройте [Lead Ads Testing Tool](https://developers.facebook.com/tools/lead-ads-testing/).
2. Выберите нужную страницу, форму и приложение; если предложен продукт — **Lead Retrieval**.
3. Откройте **Предпросмотр формы / Preview form**, заполните её контролируемыми
   тестовыми данными и отправьте. Для проверки нового лида используйте свои
   email и телефон, которых нет в CRM, включая архив. Чужие контакты не нужны.
4. Вернитесь в **Meta lead forms**. Таблица обновляется примерно раз в 10 секунд;
   появление записи может занять больше времени из-за очереди или резервной проверки.
5. В режиме **PREVIEW ONLY** новая заявка без совпадений должна получить
   **Missing in CRM**, но новая карточка CRM пока не создаётся.

Если Meta сообщает, что тестовый лид уже существует, удаляйте только ранее
созданный **тестовый** лид через инструмент Meta, убедившись, что выбрана нужная
форма. Удалять реальные заявки или CRM-карточки для запуска теста не требуется.

Если запись не появилась, проверьте ошибку в панели и раздел 10. Резервная
проверка форм запускает новый проход через 5 минут после завершения предыдущего;
при большом количестве заявок проход дольше. Само появление записи ещё не
доказывает, что она пришла именно по webhook, а не через резервную проверку.

## 7. Сверить ранее поступившие заявки и не создать дубли

Этот шаг особенно важен, если менеджеры уже переносили лидов вручную.

1. В Omnicus раскройте **Compare historical leads — no CRM changes**.
2. Выберите начало и конец периода, включая время. Один интервал — до 90 дней;
   фактическая доступность старых заявок зависит от Meta.
3. Календарь использует локальное время браузера. Начало включается, конец
   **не включается**. Например, для всего 25 сентября выбирайте с 25 сентября
   00:00 до 26 сентября 00:00, а не до 25 сентября 23:59.
4. Нажмите **Run comparison**. Интеграция должна работать в preview или live.
5. Дождитесь завершения прохода: показатель **history scans pending** должен
   вернуться к нулю без ошибки сканирования. При необходимости листайте таблицу
   через **Next page**, возвращайтесь через **First page**.

| Результат                      | Что означает и что делать                                                                                         |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| Existing CRM card              | Найдено однозначное совпадение. **Link** связывает заявку с существующей карточкой без перезаписи её полей.       |
| Missing in CRM                 | Совпадений по контактам нет. Перед **Import** проверьте CRM вручную: менеджер мог ошибиться в email или телефоне. |
| Needs review                   | Неоднозначные данные. Проверьте причину и карточки; автоматического объединения нет.                              |
| Linked to CRM                  | Заявка уже связана с карточкой; её ID указан в столбце CRM card.                                                  |
| Fetching / Queued / Delivering | Обработка ещё идёт. Не нужно многократно нажимать действия.                                                       |
| Failed / Checking delivery     | Ошибка либо результат доставки пока не подтверждён. См. раздел 10.                                                |

Система ищет совпадения по email и телефону, включая архив. По одному имени
надёжно определить человека нельзя. `MULTIPLE_MATCHES` означает, что найдено
несколько подходящих карточек: система не выбирает одну наугад.

**Run comparison ничего не импортирует.** Import и Link выполняются отдельно
для выбранной строки с подтверждением. Перед записью совпадения проверяются снова.
Эти ручные операции **не отправляют NEW LEAD** в Telegram. Данные существующих
карточек, менеджер, этап и архивное состояние не перезаписываются.

## 8. Включить рабочую доставку

1. Убедитесь, что тестовая заявка читается, выбран правильный проект CRM,
   а исторические результаты проверены.
2. Нажмите **Enable live delivery**, прочитайте подтверждение и нажмите **OK**.
3. Убедитесь, что статус — **LIVE DELIVERY**.
4. Создайте **ещё одну новую** контролируемую заявку с уникальными контактами
   после включения режима. Проверьте строку **Linked to CRM**, правильную новую
   карточку в нужной CRM и, если уведомления настроены, одно сообщение в Telegram.

Уже просмотренные строки не импортируются массово при включении LIVE: для них
остаются отдельные Import / Link. Первоначальная граница **Live cutover**
не сдвигается при переключениях. Новые подходящие заявки, в том числе найденные
резервной проверкой, обрабатываются автоматически.

Уведомление о новом лиде ожидается только при автоматическом создании новой
карточки в рабочем режиме. Совпадение с существующей карточкой, предпросмотр и
ручной исторический импорт не должны давать повторное NEW LEAD.
Заполнение формы само по себе не даёт согласия на маркетинговую рассылку.

## 9. Как обновить токен или добавить форму той же страницы

**При истечении токена:**

1. Получите новый Page Token по разделу 3.2 и проверьте нужную страницу.
2. В Omnicus нажмите **Stop**, подтвердите остановку.
3. В Connection settings вставьте новый **Page access token**.
   App Secret и verify token оставьте пустыми — сохранятся предыдущие значения.
4. Нажмите **Save disabled configuration → Test access**.
5. Верните нужный режим: **Start preview** или **Enable live delivery**,
   подтвердите действие и проверьте итоговый статус.

Одна замена Page Token не требует менять webhook, App Secret, WhatsApp или
переменные Railway. Stop не удаляет историю; уже начатые операции могут завершиться.
После возобновления резервная проверка сможет подобрать доступные пропущенные
заявки в пределах сохранённой границы, поэтому не нужно вручную массово пересоздавать их.
Строки с ошибкой после исчерпания повторов могут потребовать Recheck.

**Новая форма той же страницы:** узнайте её ID и ключи вопросов, нажмите Stop,
добавьте Form ID к существующему списку, оставьте секреты пустыми, сохраните,
выполните Test access и верните нужный режим. Проверьте тестовую заявку новой формы.
Для новой Facebook-страницы нужна отдельная настройка с учётом ограничения раздела 2.

## 10. Если что-то не работает

| Ситуация                                                  | Следующий шаг                                                                                                                                                                    |
| --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Страница не видна в Explorer                              | Проверить доступ профиля к странице, выбор страницы при авторизации и права на лиды.                                                                                             |
| `Requires pages_manage_ads`                               | Добавить указанное разрешение при выдаче токена; если его нельзя получить — обратиться к владельцу приложения.                                                                   |
| `Session has expired`, код 190 / 463                      | Обновить Page Token по разделу 9. App Secret и verify token не заменять.                                                                                                         |
| `appSecret must be longer than or equal to 16 characters` | Проверить, не вставлен ли числовой App ID вместо настоящего App Secret.                                                                                                          |
| Callback не подтверждается                                | Проверить API-домен, путь с нужным проектом, совпадение verify token и запущенный preview. Адрес сайта или `/api/v1/projects/...` не подходит.                                   |
| Успешный Test access, но новых строк нет                  | Проверить обе подписки `leadgen`, Page/Form ID, статус PREVIEW ONLY или LIVE DELIVERY и доступ к лидам. Затем отправить одну новую тестовую заявку.                              |
| `MULTIPLE_MATCHES` или другая причина Needs review        | Найти и разобрать конфликтующие карточки, включая архив; после исправления нажать **Recheck** с подтверждением. Не удалять реальные карточки без согласования.                   |
| Checking delivery / `UNKNOWN`                             | Сначала проверить CRM и передать ID строки администратору. Не повторять импорт вслепую: предыдущая попытка могла уже создать карточку.                                           |
| Карточка есть, Telegram-сообщения нет                     | Проверить, была ли это новая автоматическая LIVE-заявка. Для Link, совпадения и ручного Import уведомление не положено; иначе администратор проверяет настройки уведомлений CRM. |
| Страна не перенеслась                                     | Сравнить ключ вопроса формы с `country_of_residence:`; нестандартное поле требует адаптации.                                                                                     |
| Failed или ошибка сканирования не исчезает                | Передать администратору текст ошибки, время, проект и ID проблемной строки. Секреты и полные ответы с персональными данными не пересылать.                                       |

Общее сообщение об ошибке не всегда точно указывает причину. Если администратору
нужен подробный ответ: откройте инструменты разработчика браузера **F12 → Network**,
введите фильтр `meta-leads`, повторите только безопасную проверку **Test access**
(она доступна при остановленном приёме), откройте последний запрос `/test` → **Response**.
Передавайте только очищенные `error.code`, `message`, `details.violations` и
`correlationId`, если они есть. Не отправляйте Authorization, cookies, Request Payload
с секретами или полный HAR. Останавливать рабочую интеграцию ради диагностики
должен ответственный за неё сотрудник.

## Короткая проверка готовности

- Подключены нужные страница, формы, проект Omnicus и проект CRM.
- Page Token действителен; сроки доступа записаны и назначен ответственный за обновление.
- Webhook Page подтверждён; поле `leadgen` и подписка самой страницы включены.
- Исторические заявки проверены; спорные карточки не импортированы вслепую.
- Статус **LIVE DELIVERY**.
- Одна новая заявка после включения LIVE создала ровно одну нужную карточку;
  уведомление пришло, если оно предусмотрено настройками CRM.

После этого менеджерам не нужно вручную переносить каждую новую заявку.
Достаточно следить за ошибками и разбирать записи **Needs review**.

Для администратора: [технический контракт и ограничения интеграции](META_LEADS.md).
Названия интерфейса, права и работа токенов выше отражают проведённую настройку;
правила Meta для нового приложения нужно проверять в его кабинете. Страницы
Meta Developers при подготовке документа отвечали 429, поэтому инструкция
не выдаёт успешный тест одного аккаунта за подтверждение всех требований Meta.
